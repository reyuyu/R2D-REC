# Beam32 Context Micro-Batch Re-benchmark v2（2026-08-17，left-pad 修复后）

## 实现问题确认与修复（fc71728 结论作废）
- 旧 generate_batch 声称 left padding，实为 RIGHT padding（ids 放 [0:len]，
  pad 在尾部）：短序列最后位置是 pad token -> beam 从 pad 开始生成 -> 全 pad 输出。
  旧报告将其归因于 "transformers 5.3 + Qwen3 + FA2 left-padding beam defect" 是错误归因。
- 修复（grpo_model.generate_batch）：
  1. 真 left padding：start = max_len - len(ids)，ids 放尾部 [start:max_len]。
  2. 生成部分统一从 out[..., max_len:] 切片（generate 在所有序列的输入宽度之后
     追加新 token），不再按每条 plen 切。
  3. 保留真实 pad_token_id（151643），输出尾部 pad 清理。
  4. 新增 return_ids=True 选项（token ids 级验证）。

## 最小 deterministic 测试（修复后，Beam32 32/32/128 不变）
- A=short 单跑、B=long 单跑；batch [short,long]、[long,short]。
- batch-internal 自洽：C.short == D.short（0/32 diff）、C.long == D.long（0/32）✓
- 同形状可复现：C == E（0/32）✓
- 跨形状（batch vs single）：22-25/32 条候选 token ids 不同（exact parity=False），
  差异从第 4-14 个生成 token 分叉（浮点累积）；**等长 batch（零 padding）vs single
  同样 diff 23/32** -> 跨形状差异与 padding 无关，是 FA2 批形状（kernel 分块）的
  浮点噪声在 beam 边界处翻转后累积。
- 功能正确性：每 CoT 严格 32 candidates ✓、归属不混 ✓、invalid 一致（0）✓、
  exact/AB/A/reward 一致（reward parity=True）✓。

## 结论与推荐
- cbs=2 修复后功能正确（invalid=0、reward parity、归属不混）且不再慢 3.6x，
  但仍慢于 cbs=1（12.5 vs 9.5s/cot，1.3x），显存 69.3GB 逼近上限，long 下 OOM。
- 按判定规则（cbs=2 无性能收益）-> 正式冻结 **BEAM_CONTEXT_BATCH=1**（与 smoke
  生产路径一致；cbs=1 逐位确定、reward 确定）。
- cbs=1 的基准（typical 9.5s/cot、long 17.0s/cot）用于 ETA 重估。
